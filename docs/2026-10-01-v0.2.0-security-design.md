# Design: v0.2.0 — OAuth state and authorization fixes

**Date:** 2026-10-01
**Status:** Approved (design)
**Author:** Zoltán Tamás Szabó + Claude

First consumer: DataMind (Anest-only GA4 + Search Console datasets). DataMind keeps its own
design locally in `docs/superpowers/specs/2026-10-01-anest-google-datasets-design.md`.

## Scope

Repository: `github.com/MadBox-99/laravel-google-connect` (local `~/Herd/laravel-google-connect`).
No local app currently has it in `composer.lock`. Production consumers must be checked before
release.

## Defects in v0.1.0

1. **Forgeable `state`.** `GoogleOAuthService::getAuthorizationUrl()` sends the raw team id as
   `state`, and `GoogleOAuthController::callback()` trusts `state` to pick the team. Nothing ties the
   callback to the browser session that started the flow.
2. **No membership check.** `redirect/{team}`, `callback` and `disconnect/{team}` never check that
   the authenticated user belongs to the team. Any logged-in user can bind their own Google account
   to another team, or disconnect it, by knowing or guessing its id.
3. **Unvalidated selections.** The `GoogleConnect` Livewire component persists any posted
   `selectedSearchConsoleSiteUrl` / `selectedGa4PropertyId` / `selectedAdsCustomerId`, whether or
   not the connected account can see that resource.

## Changes

1. **Session-bound nonce.** `redirect` generates `Str::random(40)` and stores
   `google_connect.state => ['nonce' => …, 'team_id' => …]` in the session. The nonce is sent as
   `state`. `callback` pulls the session entry (it is single use and removed on read), compares it
   with `hash_equals`, and takes the team **from the session**, never from the request. A missing or
   mismatched state redirects with an error and stores nothing.
2. **Authorization.** `redirect`, `callback` and `disconnect` all authorize the user against the
   team. The default check is `$user->canAccessTenant($team)` (Filament `HasTenants`, implemented by
   every consumer). The config key `google-connect.authorize` can hold a callable that overrides
   it. Failure aborts with 403.
3. **Selection whitelist.** The Livewire `updated*` hooks persist a value only if it appears in
   the corresponding `resourceOptions()` list (or is `null`, which clears it).
4. **`google-connect.resources` config.** Default `['ads', 'search_console', 'ga4']`. The component
   renders, and `resourceOptions()` fetches, only the listed resources. DataMind sets
   `['search_console', 'ga4']`, so it never lists Ads accounts. `googleads/google-ads-php` stays a
   hard dependency so Ads consumers keep working.
5. `settings_route` / `dashboard_route` are already configurable. No change.

## Tests (Pest, testbench)

- callback with missing, wrong or reused `state` → error redirect, no `google_oauth_settings` row
- callback takes the team from the session even if the request carries another team id
- redirect / callback / disconnect for a team the user cannot access → 403
- custom `authorize` callable is honoured
- Livewire: an unlisted site or property is not persisted, a listed one is, `null` clears it
- `resources` config hides the Ads selector and skips the Ads fetch
